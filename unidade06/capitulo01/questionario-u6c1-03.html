1)
Generics — Repositório Genérico de Tarefas
Básico
Crie uma classe genérica RepositorioGenerico<T> que possa ser reaproveitada para armazenar qualquer tipo de item (Tarefa, Transacao, Contato...), evitando repetir a mesma lógica de lista em cada projeto.
Requisitos
  • Declare a classe como RepositorioGenerico<T>, com uma List<T> interna
  • Implemente adicionar(T item), remover(T item) e listarTodos()
  • O método listarTodos() deve retornar uma List<T>
Solução
import java.util.ArrayList; import java.util.List; public class RepositorioGenerico<T> { private List<T> itens = new ArrayList<>(); public void adicionar(T item) { itens.add(item); } public void remover(T item) { itens.remove(item); } public List<T> listarTodos() { return itens; } } // uso no TaskManager: RepositorioGenerico<Tarefa> repositorio = new RepositorioGenerico<>(); repositorio.adicionar(new Tarefa("Estudar Generics"));
💡 O mesmo RepositorioGenerico<T> funciona para Tarefa, Transacao ou Contato — essa é a vantagem de usar Generics em vez de criar uma lista específica para cada entidade.
2)
Generics — Wildcard com `? extends T`
Intermediário
Escreva um método estático contarItens que receba uma List<? extends Tarefa> (aceitando tanto Tarefa quanto suas subclasses, como TarefaPrioritaria) e retorne a quantidade de elementos.
Requisitos
  • Assinatura: public static int contarItens(List<? extends Tarefa> lista)
  • Use lista.size() para retornar a contagem
  • Teste o método com uma List<Tarefa> e com uma List<TarefaPrioritaria>
Solução
import java.util.List; public class RelatorioUtils { public static int contarItens(List<? extends Tarefa> lista) { return lista.size(); } public static void main(String[] args) { List<Tarefa> tarefas = List.of(new Tarefa("A"), new Tarefa("B")); List<TarefaPrioritaria> prioritarias = List.of(new TarefaPrioritaria("C")); System.out.println(contarItens(tarefas)); // 2 System.out.println(contarItens(prioritarias)); // 1 } }
Saída esperada no console
2 1
💡 ? extends Tarefa permite que o método aceite listas de Tarefa e de qualquer subclasse dela — flexibilidade típica de métodos que apenas leem a lista, sem adicionar itens nela.
3)
JDBC — Criar a Tabela e Salvar uma Tarefa
Intermediário
Escreva o SQL para criar a tabela tarefas do TaskManager e um método Java salvar(Tarefa tarefa) que a insere no banco usando PreparedStatement.
Requisitos
  • Colunas: id (chave primária autoincremento), titulo, descricao, concluida
  • Use "INSERT INTO tarefas (titulo, descricao, concluida) VALUES (?, ?, ?)" parametrizado
  • Obtenha a conexão a partir de uma ConexaoFactory (como visto na Unidade 04)
Solução
CREATE TABLE tarefas ( id INTEGER PRIMARY KEY AUTO_INCREMENT, titulo VARCHAR(100), descricao TEXT, concluida BOOLEAN ); public class TarefaDAO { public void salvar(Tarefa tarefa) { String sql = "INSERT INTO tarefas (titulo, descricao, concluida) VALUES (?, ?, ?)"; try (Connection con = ConexaoFactory.conectar(); PreparedStatement stmt = con.prepareStatement(sql)) { stmt.setString(1, tarefa.getTitulo()); stmt.setString(2, tarefa.getDescricao()); stmt.setBoolean(3, tarefa.isConcluida()); stmt.executeUpdate(); } catch (Exception e) { e.printStackTrace(); } } }
💡 Reaproveite a mesma ConexaoFactory e o padrão de PreparedStatement estudados na Unidade 04 (JDBC) — apenas troque a tabela e os campos conforme o projeto escolhido.
4)
JUnit — Testando o DAO com SQLite em Memória
Intermediário
Escreva um teste testSalvarTarefa que verifica se, após salvar uma tarefa no banco, ela aparece na listagem — usando uma conexão SQLite em memória criada antes de cada teste.
Requisitos
  • Use @BeforeEach para abrir a conexão jdbc:sqlite::memory: e criar a tabela
  • No teste, salve uma tarefa e depois liste todas
  • Use assertEquals(1, lista.size()) para confirmar que a tarefa foi persistida
Solução
class TarefaDAOTest { private Connection conexao; private TarefaDAO dao; @BeforeEach void setUp() throws Exception { conexao = DriverManager.getConnection("jdbc:sqlite::memory:"); conexao.createStatement().execute( "CREATE TABLE tarefas (id INTEGER PRIMARY KEY, titulo TEXT, descricao TEXT, concluida BOOLEAN)"); dao = new TarefaDAO(conexao); } @Test void testSalvarTarefa() { dao.salvar(new Tarefa("Estudar JUnit", "Fazer os exercícios", false)); List<Tarefa> lista = dao.listarTodas(); assertEquals(1, lista.size()); } @AfterEach void tearDown() throws Exception { conexao.close(); } }
Resultado ao rodar o teste
✓ PASSOU testSalvarTarefa() Tests run: 1, Failures: 0
💡 Como o banco é criado do zero em memória a cada @BeforeEach, o teste fica isolado: nenhum teste depende de dados deixados por outro.
5)
Ciclo Completo — Validador de Título de Tarefa
Avançado
Combinando Generics, validação e TDD (como visto na Unidade 05), implemente um ValidadorDeTitulo que lança uma exceção quando o título de uma tarefa está vazio ou tem menos de 3 caracteres, seguindo o ciclo Red → Green.
Requisitos
  • Red: escreva um teste que espera IllegalArgumentException para título "" e outro para título "ab"
  • Red: escreva um teste que confirma que um título válido (3+ caracteres) não lança exceção
  • Green: implemente public static void validar(String titulo) lançando IllegalArgumentException quando inválido
Solução
// RED — testes escritos primeiro @Test void testTituloVazioLancaExcecao() { assertThrows(IllegalArgumentException.class, () -> ValidadorDeTitulo.validar("")); } @Test void testTituloCurtoLancaExcecao() { assertThrows(IllegalArgumentException.class, () -> ValidadorDeTitulo.validar("ab")); } @Test void testTituloValidoNaoLancaExcecao() { assertDoesNotThrow(() -> ValidadorDeTitulo.validar("Estudar Java")); } // GREEN — implementação mínima public class ValidadorDeTitulo { private static final int TAMANHO_MINIMO = 3; public static void validar(String titulo) { if (titulo == null || titulo.length() < TAMANHO_MINIMO) { throw new IllegalArgumentException("Título deve ter ao menos 3 caracteres"); } } }
Resultado ao rodar os testes
✓ PASSOU testTituloVazioLancaExcecao() ✓ PASSOU testTituloCurtoLancaExcecao() ✓ PASSOU testTituloValidoNaoLancaExcecao() Tests run: 3, Failures: 0
💡 Esse mesmo padrão — validar antes de salvar, com testes para os casos inválidos e válidos — pode ser reaproveitado no FinTrack (valor da transação) e na Agenda de Contatos (ValidadorEmail).
