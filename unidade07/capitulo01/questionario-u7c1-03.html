Hibernate com MySQL na Prática 5 questões Nível Básico a Avançado

Monte, passo a passo, um projeto Java que persiste produtos no MySQL usando Hibernate/JPA. Cada questão aplica um conceito deste capítulo: mapeamento de entidades, configuração (persistence.xml), EntityManagerFactory/SessionFactory, EntityManager/Session e transações. Leia o enunciado, tente resolver por conta própria e depois revele a solução para conferir.

0/5
reveladas
1)
Mapear a Entidade Produto
Básico
Crie a classe Produto no pacote br.org.irede.loja.model e mapeie-a com anotações JPA para que o Hibernate a transforme na tabela produtos do MySQL.
Requisitos
  • Anote a classe com @Entity e @Table(name = "produtos")
  • Atributo Long id como chave primária, gerada pelo AUTO_INCREMENT do MySQL
  • Atributo String nome obrigatório, com no máximo 100 caracteres
  • Atributo Double preco
  • Construtor vazio (exigido pela JPA), construtor com nome e preco, getters e setters
Solução
package br.org.irede.loja.model; import jakarta.persistence.*; @Entity @Table(name = "produtos") public class Produto { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(nullable = false, length = 100) private String nome; private Double preco; public Produto() { } public Produto(String nome, Double preco) { this.nome = nome; this.preco = preco; } public Long getId() { return id; } public void setId(Long id) { this.id = id; } public String getNome() { return nome; } public void setNome(String nome) { this.nome = nome; } public Double getPreco() { return preco; } public void setPreco(Double preco) { this.preco = preco; } @Override public String toString() { return id + " - " + nome + " (R$ " + preco + ")"; } }
mysql> DESCRIBE produtos; (tabela criada pelo Hibernate)
+-------+--------------+------+-----+---------+----------------+ | Field | Type | Null | Key | Default | Extra | +-------+--------------+------+-----+---------+----------------+ | id | bigint | NO | PRI | NULL | auto_increment | | nome | varchar(100) | NO | | NULL | | | preco | double | YES | | NULL | | +-------+--------------+------+-----+---------+----------------+
💡 Repare que você não escreveu nenhum CREATE TABLE: com hibernate.hbm2ddl.auto = update, o Hibernate lê as anotações e cria a tabela sozinho. O construtor vazio é obrigatório porque o Hibernate instancia a classe por reflexão ao ler os dados do banco.
2)
Configurar o Projeto Maven com MySQL
Básico
Configure o projeto para que o Hibernate consiga se conectar ao banco loja de um MySQL rodando em localhost:3306.
Requisitos
  • Crie o banco no MySQL com CREATE DATABASE loja;
  • Adicione ao pom.xml as dependências hibernate-core e mysql-connector-j
  • Crie o arquivo src/main/resources/META-INF/persistence.xml com a unidade de persistência lojaPU
  • Informe driver, URL, usuário e senha do MySQL, e ative hbm2ddl.auto e show_sql
Solução — pom.xml
<dependencies> <dependency> <groupId>org.hibernate.orm</groupId> <artifactId>hibernate-core</artifactId> <version>6.5.2.Final</version> </dependency> <dependency> <groupId>com.mysql</groupId> <artifactId>mysql-connector-j</artifactId> <version>8.4.0</version> </dependency> </dependencies>
Solução — META-INF/persistence.xml
<?xml version="1.0" encoding="UTF-8"?> <persistence xmlns="https://jakarta.ee/xml/ns/persistence" version="3.0"> <persistence-unit name="lojaPU" transaction-type="RESOURCE_LOCAL"> <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider> <class>br.org.irede.loja.model.Produto</class> <properties> <!-- Conexão com o MySQL --> <property name="jakarta.persistence.jdbc.driver" value="com.mysql.cj.jdbc.Driver"/> <property name="jakarta.persistence.jdbc.url" value="jdbc:mysql://localhost:3306/loja"/> <property name="jakarta.persistence.jdbc.user" value="root"/> <property name="jakarta.persistence.jdbc.password" value="root"/> <!-- Comportamento do Hibernate --> <property name="hibernate.hbm2ddl.auto" value="update"/> <property name="hibernate.show_sql" value="true"/> </properties> </persistence-unit> </persistence>
💡 O nome lojaPU é a "chave" que a aplicação usará para criar a fábrica (Persistence.createEntityManagerFactory("lojaPU")). Ajuste usuário e senha conforme a sua instalação do MySQL. No Hibernate 6 o dialeto do MySQL é detectado automaticamente.
3)
JPAUtil — Uma Única Fábrica para Toda a Aplicação
Intermediário
Como a SessionFactory / EntityManagerFactory é pesada e deve ser criada apenas uma vez, crie a classe utilitária JPAUtil que centraliza essa criação e fornece um novo EntityManager (Session) a cada unidade de trabalho.
Requisitos
  • Atributo private static final EntityManagerFactory criado com a unidade lojaPU
  • Método public static EntityManager getEntityManager() que devolve um novo EntityManager
  • Método public static void fechar() para encerrar a fábrica no fim da aplicação
  • Construtor privado (a classe não deve ser instanciada)
Solução
package br.org.irede.loja.util; import jakarta.persistence.EntityManager; import jakarta.persistence.EntityManagerFactory; import jakarta.persistence.Persistence; public class JPAUtil { // criada UMA ÚNICA VEZ, quando a classe é carregada private static final EntityManagerFactory FACTORY = Persistence.createEntityManagerFactory("lojaPU"); private JPAUtil() { } // um novo EntityManager (Session) para cada unidade de trabalho public static EntityManager getEntityManager() { return FACTORY.createEntityManager(); } public static void fechar() { FACTORY.close(); } }
💡 Esse é o papel da SessionFactory na arquitetura do Hibernate: pesada, thread-safe e compartilhada por toda a aplicação. Já o EntityManager retornado é leve e não thread-safe — por isso cada chamada cria um novo. Se preferir a API nativa, FACTORY.unwrap(SessionFactory.class) devolve a SessionFactory do Hibernate.
4)
Salvar e Buscar com Transação
Intermediário
Escreva a classe Main que salva dois produtos ("Caderno", 15.90 e "Lápis", 2.50) na mesma transação e, em seguida, busca o primeiro pelo id para exibi-lo no console.
Requisitos
  • Obtenha o EntityManager pela JPAUtil
  • Use begin(), persist() e commit()
  • Em caso de exceção, chame rollback() (ou tudo funciona, ou nada funciona)
  • Feche o EntityManager no finally e busque o produto com find()
Solução
package br.org.irede.loja; import br.org.irede.loja.model.Produto; import br.org.irede.loja.util.JPAUtil; import jakarta.persistence.EntityManager; import jakarta.persistence.EntityTransaction; public class Main { public static void main(String[] args) { EntityManager em = JPAUtil.getEntityManager(); EntityTransaction tx = em.getTransaction(); Produto caderno = new Produto("Caderno", 15.90); Produto lapis = new Produto("Lápis", 2.50); try { tx.begin(); em.persist(caderno); em.persist(lapis); tx.commit(); System.out.println("Produtos salvos! ids: " + caderno.getId() + ", " + lapis.getId()); } catch (Exception e) { if (tx.isActive()) tx.rollback(); System.out.println("Erro ao salvar: " + e.getMessage()); } finally { em.close(); } // nova unidade de trabalho = novo EntityManager EntityManager em2 = JPAUtil.getEntityManager(); Produto encontrado = em2.find(Produto.class, caderno.getId()); System.out.println("Encontrado: " + encontrado); em2.close(); JPAUtil.fechar(); } }
Saída no console
Hibernate: insert into produtos (nome,preco) values (?,?) Hibernate: insert into produtos (nome,preco) values (?,?) Produtos salvos! ids: 1, 2 Hibernate: select p1_0.id,p1_0.nome,p1_0.preco from produtos p1_0 where p1_0.id=? Encontrado: 1 - Caderno (R$ 15.9)
💡 O tx.isActive() evita tentar desfazer uma transação que nem chegou a começar. Note também que nenhuma linha de SQL foi escrita: as linhas "Hibernate: ..." são o SQL gerado automaticamente (graças ao show_sql).
5)
ProdutoDAO — Do JDBC Manual para o ORM
Avançado
Na Unidade 04 você escreveu DAOs com JDBC, montando cada SQL e lendo o ResultSet campo a campo. Reescreva um ProdutoDAO completo (CRUD) usando apenas a API do ORM e compare a quantidade de código.
Requisitos
  • salvar(Produto p) — usa persist()
  • buscarPorId(Long id) — usa find()
  • listarTodos() — usa a consulta JPQL SELECT p FROM Produto p
  • atualizar(Produto p) — usa merge()
  • remover(Long id) — usa find() + remove()
  • Toda operação de escrita deve rodar dentro de uma transação, com rollback() em caso de erro
Solução
package br.org.irede.loja.dao; import br.org.irede.loja.model.Produto; import br.org.irede.loja.util.JPAUtil; import jakarta.persistence.EntityManager; import jakarta.persistence.EntityTransaction; import java.util.List; import java.util.function.Consumer; public class ProdutoDAO { public void salvar(Produto p) { executarEmTransacao(em -> em.persist(p)); } public Produto buscarPorId(Long id) { try (EntityManager em = JPAUtil.getEntityManager()) { return em.find(Produto.class, id); } } public List<Produto> listarTodos() { try (EntityManager em = JPAUtil.getEntityManager()) { return em.createQuery("SELECT p FROM Produto p ORDER BY p.nome", Produto.class) .getResultList(); } } public void atualizar(Produto p) { executarEmTransacao(em -> em.merge(p)); } public void remover(Long id) { executarEmTransacao(em -> { Produto p = em.find(Produto.class, id); if (p != null) em.remove(p); }); } // begin / commit / rollback em um só lugar private void executarEmTransacao(Consumer<EntityManager> acao) { EntityManager em = JPAUtil.getEntityManager(); EntityTransaction tx = em.getTransaction(); try { tx.begin(); acao.accept(em); tx.commit(); } catch (RuntimeException e) { if (tx.isActive()) tx.rollback(); throw e; } finally { em.close(); } } }
Comparativo (mesmo CRUD de Produto)
JDBC manual ORM (Hibernate) SQL escrito à mão 5 comandos 0 (1 consulta JPQL) ResultSet → objeto manual (2x) automático setString/setDouble... ~10 chamadas nenhuma Linhas no DAO ~90 ~50
💡 O método executarEmTransacao evita repetir o bloco begin/commit/rollback em cada operação. O try-with-resources com EntityManager funciona porque, a partir da JPA 3.1 (Hibernate 6.2+), ele implementa AutoCloseable. Os números do comparativo são aproximados e servem para ilustrar a redução de código repetitivo.
