Mapeamento Objeto-Relacional (ORM) Object-Relational Mapping

ORM é uma técnica que cria uma camada de abstração entre a aplicação (orientada a objetos) e o banco de dados (relacional).

Como funciona? Você manipula objetos no seu código. O ORM traduz suas ações em comandos SQL (INSERT, UPDATE, DELETE, SELECT) e converte os resultados do banco de dados de volta para objetos.

Objeto Java → ORM (Hibernate) → SQL → MySQL Objeto Java ← ORM (Hibernate) ← ResultSet ← MySQL

O ORM resolve a diferença entre os dois "mundos" — conhecida como impedância objeto-relacional:

Mundo Orientado a ObjetosMundo Relacional
Classe ProdutoTabela produtos
Atributo nomeColuna nome
Objeto (instância)Linha (registro)
Identidade do objetoChave primária (PK)
Referência a outro objetoChave estrangeira (FK)
Exemplo Prático: Sem ORM vs. Com ORM Mesmo resultado

Sem ORM — você escreve o SQL manualmente:

INSERT INTO PRODUTO (NOME, PRECO) VALUES ('Caneta', 1.99);

Com ORM — você trabalha apenas com o objeto:

Produto produto = new Produto("Caneta", 1.99); entityManager.persist(produto); // o Hibernate gera o INSERT

Na Unidade 04 você usou JDBC para fazer isso — abrindo conexão, montando o PreparedStatement, preenchendo cada ? e lendo o ResultSet campo a campo. Com ORM, todo esse trabalho repetitivo é feito pelo framework.

Os Benefícios Estratégicos do ORM 4 Vantagens

A adoção de um framework ORM traz vantagens significativas para o ciclo de vida de um projeto de software:

🚀 Produtividade Acelerada: menos código repetitivo (SQL, conversão de ResultSet, abertura/fechamento de recursos). O desenvolvedor foca na regra de negócio.

🔧 Manutenibilidade Aprimorada: adicionar um atributo na classe é suficiente para que ele seja persistido — não é preciso caçar e alterar dezenas de comandos SQL espalhados.

🔄 Independência do Banco de Dados: o ORM gera o SQL no "dialeto" de cada banco. Trocar MySQL por PostgreSQL, por exemplo, exige basicamente alterar a configuração.

⚡ Performance Otimizada: recursos como cache de primeiro nível, carregamento sob demanda (lazy loading) e envio de comandos em lote reduzem idas ao banco.

Hibernate Framework ORM

🔹 Criado por Gavin King no início dos anos 2000 (primeira versão em 2001).

🔹 É um framework robusto que, por muitos anos, definiu o padrão de como a persistência de dados é feita em Java — e inspirou a especificação oficial JPA (Java/Jakarta Persistence API).

🔹 Objetivos centrais: ser um framework transparente intuitivo poderoso

JPA x Hibernate: a JPA é a especificação (o "contrato", só interfaces e anotações). O Hibernate é a implementação mais usada dessa especificação — e ainda oferece sua própria API nativa.

Arquitetura em Camadas Do código ao banco

O acesso a dados em uma aplicação Java com Hibernate é organizado em camadas:

┌────────────────────────────────────────────────┐ │ Data Access Layer (sua aplicação) │ └────────────────────────────────────────────────┘ ↓ ↓ ┌──────────────────────┐ ┌──────────────────────┐ │ Java Persistence API │ │ Hibernate Native API │ └──────────────────────┘ └──────────────────────┘ ↓ ↓ ┌────────────────────────────────────────────────┐ │ Hibernate │ └────────────────────────────────────────────────┘ ↓ ┌────────────────────────────────────────────────┐ │ JDBC │ └────────────────────────────────────────────────┘ ↓ 🛢 Banco Relacional (MySQL)

A aplicação pode usar a JPA (padrão) ou a API nativa do Hibernate (específica). Ambas são implementadas pelo Hibernate, que por sua vez usa o JDBC para se comunicar com o banco. Ou seja: o ORM não substitui o JDBC — ele o utiliza por baixo dos panos.

Arquitetura Principal: SessionFactory Pesado · Thread-safe

O que faz?

🔹 Lê as configurações (persistence.xml);

🔹 Conhece todos os mapeamentos (sabe como transformar Produto em produtos);

🔹 Cria e fornece as Session.

⚠ Criada apenas UMA VEZ quando a aplicação inicia. É um processo caro!
// JPA: EntityManagerFactory (no Hibernate, é a SessionFactory) private static final EntityManagerFactory emf = Persistence.createEntityManagerFactory("lojaPU");
Arquitetura Principal: Session Leve · Vida curta

Um objeto leve, de vida curta e não thread-safe.

O que faz?

🔹 É a sua interface principal para o banco de dados;

🔹 Realiza as operações: persist() (salvar), find() (buscar), remove() (deletar);

🔹 Gerencia o cache de primeiro nível (contexto de persistência).

💡 Abra, use e feche. Uma nova Session para cada unidade de trabalho.
// JPA: EntityManager (no Hibernate, é a Session) EntityManager em = emf.createEntityManager(); Produto p = em.find(Produto.class, 1L); em.close();
Arquitetura Principal: Transaction Unidade atômica

O que faz? Garante a integridade dos dados: ou todas as operações funcionam, ou nenhuma funciona.

MétodoSignificado
transaction.begin()"Começar a operação."
transaction.commit()"Confirmar e salvar tudo no banco."
transaction.rollback()"Deu erro! Desfazer tudo."
EntityTransaction tx = em.getTransaction(); try { tx.begin(); em.persist(produto); tx.commit(); } catch (Exception e) { tx.rollback(); } finally { em.close(); }

Mapeando uma Entidade Anotações

Para o ORM saber como transformar a classe em tabela, usamos anotações da JPA:

import jakarta.persistence.*; @Entity @Table(name = "produtos") public class Produto { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(nullable = false, length = 100) private String nome; private Double preco; public Produto() { } // construtor vazio obrigatório // construtor com campos, getters e setters... }

@Entity: a classe é uma entidade persistente. @Table: nome da tabela. @Id: chave primária. @GeneratedValue(IDENTITY): usa o AUTO_INCREMENT do MySQL. @Column: detalhes da coluna.

Configurando o Hibernate com MySQL Maven + persistence.xml

1. Dependências no pom.xml:

<dependency> <groupId>org.hibernate.orm</groupId> <artifactId>hibernate-core</artifactId> <version>6.5.2.Final</version> </dependency> <dependency> <groupId>com.mysql</groupId> <artifactId>mysql-connector-j</artifactId> <version>8.4.0</version> </dependency>

2. Configuração em src/main/resources/META-INF/persistence.xml:

<persistence-unit name="lojaPU"> <class>br.org.irede.loja.model.Produto</class> <properties> <property name="jakarta.persistence.jdbc.url" value="jdbc:mysql://localhost:3306/loja"/> <property name="jakarta.persistence.jdbc.user" value="root"/> <property name="jakarta.persistence.jdbc.password" value="root"/> <property name="hibernate.hbm2ddl.auto" value="update"/> <property name="hibernate.show_sql" value="true"/> </properties> </persistence-unit>

hbm2ddl.auto = update: o Hibernate cria/atualiza as tabelas a partir das entidades. show_sql = true: exibe no console o SQL gerado — ótimo para aprender! Antes de rodar, crie o banco no MySQL: CREATE DATABASE loja;

Nenhuma abordagem é "sempre melhor": ORM acelera a maior parte do CRUD, enquanto JDBC puro ainda é útil em consultas muito específicas ou de altíssima performance.

acertos
Questão 1 — O ORM elimina o uso do JDBC: o Hibernate se comunica diretamente com o MySQL sem passar por ele.
Questão 2 — A SessionFactory é um objeto pesado e deve ser criada apenas uma vez, quando a aplicação inicia.
Questão 3 — Uma mesma Session pode ser compartilhada com segurança entre várias threads durante toda a vida da aplicação.
Questão 4 — Se ocorrer um erro no meio de uma transação, rollback() desfaz todas as operações feitas desde o begin().
Questão 5 — Com ORM, o comando entityManager.persist(produto) equivale a escrever manualmente um INSERT no banco.

🚀 Curiosidades sobre ORM, Hibernate e MySQL
😤
O Hibernate nasceu de uma frustração
Gavin King criou o Hibernate em 2001 como alternativa aos Entity Beans do EJB 2, considerados complexos e pesados demais. A ideia era permitir persistir objetos Java simples (POJOs), sem herdar classes especiais do framework.
📜
O Hibernate inspirou o padrão oficial
A JPA surgiu em 2006, com o Java EE 5, fortemente influenciada pelo Hibernate — o próprio Gavin King participou do grupo de especificação. Em 2020, com o Jakarta EE 9, os pacotes mudaram de javax.persistence para jakarta.persistence.
🐬
O "My" do MySQL é um nome
O MySQL foi criado em 1995 pela empresa sueca MySQL AB. O nome vem de My, filha de Michael "Monty" Widenius, um dos fundadores. O MySQL foi comprado pela Sun em 2008, que por sua vez foi adquirida pela Oracle em 2010.
💬
"O Vietnã da Ciência da Computação"
Em 2006, Ted Neward publicou um ensaio famoso comparando o ORM a uma guerra sem fim, por causa da dificuldade de conciliar perfeitamente objetos e tabelas. Mesmo assim, o ORM se tornou a abordagem mais comum de persistência em Java.
🔍
O cache de primeiro nível economiza consultas
Se você chamar em.find(Produto.class, 1L) duas vezes na mesma Session, o Hibernate executa o SELECT apenas uma vez — a segunda chamada devolve o objeto que já está no contexto de persistência.
⚠
Cuidado com o problema N+1
Um erro clássico de quem usa ORM: buscar uma lista com 1 consulta e, ao acessar um relacionamento de cada item, disparar mais N consultas. Ativar o show_sql ajuda a enxergar esse tipo de problema cedo.
