01
IniciarRepositorio git init
Você criou a pasta meu-projeto/ e quer começar a versionar o código com Git. Escreva os dois primeiros comandos necessários: o que inicializa o repositório e o que verifica se deu certo.
O que fazer
Inicializar o repositório Git na pasta atual
Verificar o estado inicial (nenhum commit ainda)
Comandos
$ git init Initialized empty Git repository in /meu-projeto/.git/ $ git status On branch main No commits yet nothing to commit (create/copy files and use "git add" to track)
git init cria a pasta .git/ com toda a estrutura interna do repositório. git status confirma que está tudo certo e mostra que não há commits ainda.
02
PrimeiroCommit git addgit commit
Você criou o arquivo README.md na pasta do projeto. Escreva os comandos para adicionar esse arquivo ao staging e criar o primeiro commit com a mensagem "Adiciona README inicial".
O que fazer
Adicionar o arquivo README.md ao staging
Criar commit com mensagem descritiva
Comandos
$ git add README.md $ git commit -m "Adiciona README inicial" [main (root-commit) c1a4f56] Adiciona README inicial 1 file changed, 3 insertions(+) create mode 100644 README.md
git add README.md move o arquivo para a Staging Area. git commit -m "..." cria o snapshot permanente. O output mostra a branch, o hash abreviado e o que mudou.
03
AdicionarTudo git add .
Você editou 3 arquivos (App.java, Config.java, utils/Helper.java) e criou um novo (Model.java). Quer adicionar tudo de uma vez ao staging e depois commitar.
O que fazer
Adicionar todos os arquivos (incluindo subpastas) ao staging com um único comando
Verificar o status para confirmar
Criar commit
Comandos
$ git add . $ git status Changes to be committed: modified: App.java modified: Config.java modified: utils/Helper.java new file: Model.java $ git commit -m "Refatora classes principais e adiciona Model"
git add . adiciona tudo recursivamente a partir da pasta atual. O ponto (.) representa o diretório atual. Confirme sempre com git status antes de commitar.
04
VerDiferencas git diff
Você editou App.java mas ainda não deu git add. Quer ver o que exatamente mudou no arquivo antes de adicionar ao staging. Depois, adiciona ao staging e quer ver o que vai entrar no commit.
O que fazer
Ver diferenças no working directory (antes do staging)
Adicionar ao staging
Ver diferenças no staging (antes do commit)
Comandos
# Ver mudanças não staged (working dir vs último commit) $ git diff diff --git a/App.java b/App.java --- a/App.java +++ b/App.java @@ -5,6 +5,7 @@ + System.out.println("Nova linha adicionada"); $ git add App.java # Ver mudanças staged (staging vs último commit) $ git diff --staged
git diff (sem flags) mostra o que ainda não foi "adicionado". git diff --staged mostra o que já está no staging e vai entrar no próximo commit. São dois momentos diferentes da inspecção.
05
HistoricoCompacto git log
O projeto já tem vários commits. Você quer ver o histórico completo de forma compacta e com gráfico, incluindo todas as branches. Em seguida, quer ver os detalhes de um commit específico pelo hash.
O que fazer
Exibir histórico compacto com gráfico de todas as branches
Ver detalhes de um commit específico (use o hash b7e2d09)
Comandos
$ git log --oneline --graph --all * d9e2b47 (HEAD -> main) feat: adiciona relatório PDF * b7e2d09 fix: corrige cálculo de total * c1a4f56 chore: configuração inicial # Ver detalhes de um commit específico $ git show b7e2d09
--oneline compacta para 1 linha, --graph desenha o gráfico ASCII das branches, --all inclui todas as branches. O git show <hash> exibe os detalhes e o diff de um commit específico.
06
CorrigirCommit git commit --amend
Você fez um commit com a mensagem "corrige bug" mas percebeu que: (1) a mensagem está vaga demais e (2) esqueceu de adicionar o arquivo CHANGELOG.md. O commit ainda não foi publicado (sem push). Corrija.
O que fazer
Adicionar o arquivo esquecido ao staging
Reescrever o último commit incluindo o arquivo e nova mensagem
Comandos
# Adicionar o arquivo esquecido ao staging $ git add CHANGELOG.md # Reescrever o último commit com nova mensagem $ git commit --amend -m "fix: corrige NullPointerException no módulo de pagamento" [main b7e2d09] fix: corrige NullPointerException no módulo de pagamento Date: ... 2 files changed, 15 insertions(+)
git commit --amend substitui o último commit por um novo (com novo hash). Tudo que estava no staging junto com o que já estava no commit anterior é consolidado. Nunca use após push!
07
ConfigurarIdentidade git config
Em um computador novo, você precisa configurar seu nome e e-mail no Git globalmente (para todos os repositórios). Configure com o nome Ana Silva e e-mail ana@empresa.com.
O que fazer
Configurar nome global
Configurar e-mail global
Verificar as configurações aplicadas
Comandos
$ git config --global user.name "Ana Silva" $ git config --global user.email "ana@empresa.com" # Verificar todas as configurações $ git config --list user.name=Ana Silva user.email=ana@empresa.com
O flag --global aplica a configuração para todos os repositórios do usuário, salvando em ~/.gitconfig. Sem --global, só afeta o repositório atual. Nome e e-mail aparecem em todo commit.
08
ClonarRepositorio git clone
Você recebeu o link do repositório do projeto: https://github.com/empresa/sistema-rh.git. Quer clonar o repositório na sua máquina e depois entrar na pasta e ver o histórico.
O que fazer
Clonar o repositório remoto
Entrar na pasta criada
Ver o histórico compacto
Comandos
$ git clone https://github.com/empresa/sistema-rh.git Cloning into 'sistema-rh'... remote: Enumerating objects: 142, done. remote: Counting objects: 100% (142/142), done. Receiving objects: 100% (142/142), done. $ cd sistema-rh $ git log --oneline
git clone <url> copia o repositório completo (histórico, branches, tags) e já configura o remote origin apontando para a URL original. A pasta criada tem o nome do repositório.
09
GitIgnore .gitignore
Seu projeto Java gera arquivos .class compilados e tem uma pasta target/ com os builds. Você também tem um arquivo .env com senhas. Crie o .gitignore para ignorar tudo isso, depois verifique se funcionou.
O que fazer
Criar o arquivo .gitignore com os padrões adequados
Verificar que os arquivos não aparecem mais como untracked
Conteúdo do .gitignore
# Arquivos compilados Java *.class # Pasta de build target/ # Arquivo de variáveis de ambiente (NUNCA versionar senhas!) .env # IDEs .idea/ *.iml
Verificar
$ git status Untracked files: .gitignore # target/, .class e .env NÃO aparecem mais! $ git add .gitignore $ git commit -m "chore: adiciona .gitignore"
O .gitignore aceita padrões glob: *.class ignora todos os arquivos .class, target/ ignora a pasta inteira. Sempre adicione e commite o próprio .gitignore para que a equipe use o mesmo.
10
FluxoCompleto workflow
Simule o fluxo completo de um desenvolvedor iniciando um projeto do zero: criar repositório, configurar identidade, criar .gitignore, fazer primeiro commit e verificar o histórico.
Passo a passo
Criar e entrar na pasta do projeto
Iniciar o repositório
Configurar nome e e-mail (se ainda não estiverem)
Criar .gitignore e README.md
Fazer o commit inicial
Verificar o histórico
Fluxo completo
# 1. Criar e entrar na pasta $ mkdir meu-projeto && cd meu-projeto # 2. Iniciar repositório $ git init # 3. Configurar identidade (primeira vez) $ git config --global user.name "Seu Nome" $ git config --global user.email "seu@email.com" # 4. Criar arquivos iniciais $ echo "# Meu Projeto" > README.md $ echo "*.class" > .gitignore $ echo "target/" >> .gitignore # 5. Staging e commit inicial $ git add . $ git commit -m "chore: inicializa projeto com README e .gitignore" [main (root-commit) a3f8c12] chore: inicializa projeto # 6. Verificar histórico $ git log --oneline a3f8c12 (HEAD -> main) chore: inicializa projeto com README e .gitignore
Este é o fluxo padrão para qualquer projeto novo. A convenção Conventional Commits usa prefixos como chore:, feat:, fix:, docs: nas mensagens para facilitar a leitura do histórico.
