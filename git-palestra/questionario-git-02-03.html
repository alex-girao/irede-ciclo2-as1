01
CriarFeatureBranch git checkout -b
Você está na branch main e precisa iniciar o desenvolvimento de uma nova funcionalidade de cadastro de usuários. Crie uma branch chamada feature/cadastro-usuario e já troque para ela.
O que fazer
Criar e trocar para a nova branch em um comando
Confirmar em qual branch você está
Comandos
# Opção clássica $ git checkout -b feature/cadastro-usuario Switched to a new branch 'feature/cadastro-usuario' # Opção moderna (Git 2.23+) $ git switch -c feature/cadastro-usuario # Confirmar branch atual $ git branch * feature/cadastro-usuario main
O asterisco (*) no git branch indica a branch ativa. O flag -b (checkout) ou -c (switch) combina criar e trocar em um só comando.
02
ListarBranches git branch
Você quer ver todas as branches do projeto: as locais, as remotas e um resumo de ambas. Liste-as de três formas diferentes.
O que fazer
Listar apenas branches locais
Listar apenas branches remotas
Listar locais e remotas juntas
Comandos
# Branches locais $ git branch * main feature/login # Branches remotas $ git branch -r origin/main origin/feature/login # Todas (locais + remotas) $ git branch -a * main feature/login remotes/origin/main remotes/origin/feature/login
-r = remote, -a = all. As branches remotas aparecem com o prefixo remotes/origin/ para diferenciar das locais.
03
MergeFeature git merge
A feature feature/relatorio-pdf foi concluída e revisada. Agora você precisa integrá-la à branch main. Faça o merge e depois delete a branch de feature.
O que fazer
Trocar para a branch main
Fazer o merge da feature
Deletar a branch de feature (já mergeada)
Comandos
# Ir para main $ git switch main # Mergear a feature $ git merge feature/relatorio-pdf Updating a3f8c12..d9e2b47 Fast-forward relatorio/PdfService.java | 87 ++++++++++++ # Deletar branch já mergeada $ git branch -d feature/relatorio-pdf Deleted branch feature/relatorio-pdf (was d9e2b47).
Sempre faça merge a partir da branch de destino (main). O -d só deleta branches já mergeadas — use -D para forçar deleção (com cuidado!).
04
ResolverConflito merge conflict
Ao mergear feature/pagamento em main, o Git reporta um conflito em src/Checkout.java. Ambas as branches editaram as mesmas linhas. Descreva o fluxo completo de resolução.
O que fazer
Identificar os arquivos em conflito
Editar e resolver o conflito manualmente
Adicionar ao staging e finalizar o merge
Fluxo de resolução
$ git merge feature/pagamento CONFLICT (content): Merge conflict in src/Checkout.java Automatic merge failed; fix conflicts and then commit the result. # Ver quais arquivos têm conflito $ git status both modified: src/Checkout.java # O arquivo terá marcadores como: # <<<<<<< HEAD # código da main # ======= # código da feature # >>>>>>> feature/pagamento # Após editar e resolver o conflito: $ git add src/Checkout.java $ git commit [main e4a1b23] Merge branch 'feature/pagamento'
Os marcadores <<<<<<<, =======, >>>>>>> delimitam o conflito. Edite o arquivo mantendo o código correto e removendo todos os marcadores antes do git add. IDEs modernas facilitam isso com painéis visuais.
05
RebaseLocal git rebase
Você está na branch feature/login e enquanto trabalhava, a main recebeu novos commits. Antes de abrir o PR, você quer que sua branch parta dos commits mais recentes da main (histórico linear).
O que fazer
Atualizar a main local
Fazer rebase da feature em cima da main atualizada
Comandos
# Atualizar main sem sair da feature branch $ git fetch origin # Fazer rebase da feature em cima da main atualizada $ git rebase origin/main Successfully rebased and updated refs/heads/feature/login. # Se houver conflitos durante o rebase: # 1. Resolver o conflito no arquivo # 2. git add <arquivo> # 3. git rebase --continue # Para cancelar: git rebase --abort
Use git fetch origin antes para ter o estado mais recente do remoto. O rebase é adequado aqui pois a branch é local e privada — não foi publicada ainda. O resultado é um histórico linear mais fácil de ler.
06
HotfixEmergencial hotfix
Produção caiu! Há um bug crítico em main. Você está no meio de uma feature em feature/login. Faça o hotfix sem perder seu trabalho atual.
O que fazer
Salvar o trabalho atual sem commitar
Criar branch de hotfix a partir de main
Corrigir, commitar e mergear em main
Voltar para a feature e recuperar o trabalho
Fluxo de hotfix
# Salvar trabalho atual sem commitar $ git stash Saved working directory and index state WIP on feature/login # Criar hotfix a partir de main $ git switch main $ git switch -c hotfix/crash-checkout # Corrigir o bug, commitar $ git add . $ git commit -m "fix: corrige crash no checkout" # Mergear em main $ git switch main $ git merge hotfix/crash-checkout $ git branch -d hotfix/crash-checkout # Voltar para a feature e recuperar o trabalho $ git switch feature/login $ git stash pop
git stash guarda o trabalho em andamento. git stash pop recupera. O fluxo hotfix é clássico: branch de main → corrige → merge em main → merge em develop (para não perder o fix na próxima release).
07
MergeNoFastForward --no-ff
Ao mergear uma feature branch, você quer sempre criar um merge commit, mesmo que seja possível um fast-forward. Isso preserva o contexto de qual conjunto de commits veio de qual feature.
O que fazer
Mergear feature em main forçando a criação de merge commit
Comandos
$ git switch main # --no-ff força criação de merge commit mesmo em fast-forward $ git merge --no-ff feature/dashboard -m "Merge feature/dashboard: adiciona painel de controle" Merge made by the 'recursive' strategy. # git log mostrará claramente o merge commit $ git log --oneline --graph * (HEAD -> main) Merge feature/dashboard: adiciona painel de controle |\\ | * Adiciona gráficos ao dashboard | * Cria estrutura do dashboard |/ * Commit anterior
--no-ff (no fast-forward) garante que sempre haverá um merge commit. Isso é preferido em muitos projetos para preservar a rastreabilidade de qual feature veio de onde no histórico.
08
DeletarBranchRemota git push --delete
Após o merge e review do PR, você precisa deletar a branch feature/relatorio tanto localmente quanto no repositório remoto.
O que fazer
Deletar a branch local
Deletar a branch remota
Comandos
# Deletar branch local $ git branch -d feature/relatorio Deleted branch feature/relatorio (was d9e2b47). # Deletar branch remota (duas sintaxes equivalentes) $ git push origin --delete feature/relatorio # ou: $ git push origin :feature/relatorio To https://github.com/empresa/projeto.git - [deleted] feature/relatorio
A sintaxe git push origin --delete <branch> é mais legível. A sintaxe :branch (dois pontos + nome) é a forma antiga, equivalente. No GitHub/GitLab, você também pode deletar pelo botão na interface do PR.
09
SquashCommits merge --squash
A branch feature/importacao-csv tem 8 commits de "WIP" e rascunhos. Ao mergear, você quer condensar tudo em um único commit limpo na main.
O que fazer
Mergear usando squash para combinar todos os commits
Criar o commit final com mensagem descritiva
Comandos
$ git switch main # Squash: combina os commits da feature em staged changes $ git merge --squash feature/importacao-csv Squash commit -- not updating HEAD Automatic merge went well; stopped before committing as requested # Criar o commit final com mensagem limpa $ git commit -m "feat: adiciona importação de dados via CSV" [main f3c2e11] feat: adiciona importação de dados via CSV
--squash coloca todas as mudanças da feature branch no staging, sem criar o merge commit. Você então cria um único commit com a mensagem que deseja. Cuidado: a branch original não é marcada como mergeada, então use -D para deletar depois.
10
WorkflowCompleto feature flow
Simule o ciclo completo de uma feature: criar branch a partir de main, desenvolver, integrar atualizações de main, mergear e fazer limpeza.
Passo a passo
Criar branch feature a partir de main
Fazer commits de desenvolvimento
Buscar atualizações de main (sem merge automático)
Fazer rebase sobre main atualizada
Mergear em main com merge commit explícito
Deletar a branch local e remota
Ciclo completo de feature
# 1. Criar feature branch $ git switch main $ git switch -c feature/notificacoes # 2. Desenvolver e commitar $ git add . && git commit -m "feat: cria serviço de notificações" $ git add . && git commit -m "feat: adiciona templates de email" # 3. Buscar atualizações de main sem mesclar $ git fetch origin # 4. Rebase sobre main atualizada $ git rebase origin/main # 5. Mergear em main com merge commit $ git switch main $ git pull # garantir main local atualizada $ git merge --no-ff feature/notificacoes -m "Merge feat/notificacoes" $ git push # 6. Limpar branches $ git branch -d feature/notificacoes $ git push origin --delete feature/notificacoes
Este é o fluxo padrão adotado por equipes profissionais. O rebase antes do merge garante histórico linear e o --no-ff preserva o contexto da feature. Sempre faça git pull antes de mergear para evitar conflitos desnecessários.
