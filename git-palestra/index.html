📁 O que é Git?

Git é um sistema de controle de versão distribuído criado por Linus Torvalds em 2005 para gerenciar o desenvolvimento do kernel Linux. Ele registra o histórico completo de alterações de um projeto, permite trabalho paralelo em equipe e garante que nenhum código seja perdido.

🗺️ As Três Áreas do Git
ÁreaTambém chamada deO que guarda
Working DirectoryWorking TreeSeus arquivos do projeto como você os edita agora
Staging AreaIndex / CacheAlterações marcadas para entrar no próximo commit
Repository.git / Object DBHistórico permanente de todos os commits já feitos
# Fluxo básico: editar → adicionar → commitar # Working Dir → Staging Area → Repository # (edit) git add arquivo git commit -m "..."

💡 O que é HEAD?

HEAD é um ponteiro especial que indica qual é o commit atual — normalmente aponta para a ponta da branch ativa. Quando você faz um novo commit, HEAD avança automaticamente. Entender o HEAD é fundamental para comandos como git reset, git revert e git checkout.

🚀 Curiosidades — Repositório e Commits
🦸
Git foi criado em 10 dias
Linus Torvalds criou a primeira versão funcional do Git em apenas 10 dias (abril de 2005), após o BitKeeper — ferramenta que o kernel Linux usava — revogar a licença gratuita para projetos open-source.
🔢
Commits são identificados por SHA-1
Cada commit no Git recebe um hash SHA-1 de 40 caracteres hexadecimais (ex: a3f8c12...). Esse hash é calculado com base no conteúdo, autor, data e commit pai, garantindo integridade e unicidade.
📂
A pasta .git é o repositório
Todo repositório Git é autocontido na pasta oculta .git/. Isso significa que você pode copiar essa pasta para qualquer lugar e ter o histórico completo do projeto — sem depender de servidor.
💯
O nome "Git" foi intencional
Linus Torvalds disse que "git" é uma gíria britânica para pessoa idiota. Ele costuma nomear seus projetos com auto-referência: "I'm an egotistical bastard, and I name all my projects after myself. First 'Linux', now 'git'."
⚡
Git é distribuído, não centralizado
Diferente do SVN ou CVS, no Git todo desenvolvedor tem uma cópia completa do histórico. Não existe um servidor "obrigatório" — você pode trabalhar offline e sincronizar depois.

🌳 O que são Branches?

Uma branch (“ramo”) é uma linha de desenvolvimento independente. Ao criar uma branch, você pode trabalhar em uma funcionalidade, correção ou experimento sem afetar o código principal. Branches são leves no Git — criar uma nova branch é instantâneo e custa apenas um ponteiro de 40 bytes.

🔧 Comandos de Branch
ComandoFunção
git branchLista todas as branches locais
git branch <nome>Cria uma nova branch (sem trocar para ela)
git checkout <branch>Troca para a branch indicada (comando clássico)
git switch <branch>Troca para a branch indicada (comando moderno)
git checkout -b <branch>Cria E já troca para a nova branch
git switch -c <branch>Cria E já troca (versão moderna)
git merge <branch>Mescla a branch indicada NA branch atual
git rebase <branch>Reaplica commits sobre outra base
git branch -d <nome>Deleta uma branch já mesclada
↔️ Merge vs Rebase
git merge
  • Cria um merge commit
  • Preserva o histórico exato
  • Seguro para branches compartilhadas
  • Histórico pode ficar "cheio"
git rebase
  • Reescreve commits sobre nova base
  • Histórico linear e limpo
  • Não use em branches públicas!
  • Ótimo para branches locais
📋 Estratégias de Branch
BranchQuando usar
main / masterCódigo estável e pronto para produção — nunca commite direto aqui
developIntegração contínua das features antes de ir para main
feature/nomeNova funcionalidade em desenvolvimento
fix/nome ou hotfix/Correção de bug — hotfix vai direto de main para main
release/v1.0Preparação de uma versão para lançamento
💡 Fast-Forward vs 3-Way Merge
# Fast-forward: main não teve commits novos → só move o ponteiro $ git merge feature/login Updating a3f8c12..d9e2b47 Fast-forward # 3-way merge: ambas as branches evoluíram → cria merge commit $ git merge feature/carrinho Merge made by the 'recursive' strategy.

🚀 Curiosidades — Branches e Fusão
⚡
Branches são apenas ponteiros
No Git, uma branch é literalmente um arquivo texto de 40 bytes com o hash do commit atual. Criar uma branch é tão barato quanto criar um arquivo — por isso o Git incentiva criar branches para tudo.
🤝
GitHub popularizou o Pull Request
O conceito de "Pull Request" (PR) não é do Git em si, mas foi criado e popularizado pelo GitHub. No GitLab o equivalente se chama "Merge Request" (MR). Ambos são formas de revisar código antes do merge.
🌀
Git Flow vs Trunk-Based Development
O Git Flow (com develop, feature, release, hotfix) foi muito popular mas é considerado pesado por muitas equipes modernas. O Trunk-Based Development — commitar frequentemente na main — é o modelo preferido em empresas como Google e Meta.
🧹
Conflitos são normais, não erros
Conflitos de merge acontecem quando duas branches alteram a mesma linha do mesmo arquivo. O Git não sabe qual versão é "certa" — ele marca os conflitos e pede para você decidir. Conflito = colaboração ativa.
💹
O Linux tem +1000 branches ativas
O repositório oficial do kernel Linux é um dos maiores do mundo: mais de 1 milhão de commits, dezenas de branches de manutenção ativas, e contribuições de milhares de desenvolvedores por versão.

🌐 Repositórios Remotos

Um repositório remoto é uma cópia do projeto hospedada em um servidor (GitHub, GitLab, Bitbucket). O remoto padrão se chama origin. Permite colaboração entre múltiplos desenvolvedores e serve como backup do projeto.

🔧 Comandos Remotos
ComandoFunção
git remote -vLista os repositórios remotos configurados e suas URLs
git pushEnvia commits locais para o remoto
git push origin <branch>Envia uma branch específica para o remoto
git pullBusca alterações do remoto E já faz merge (fetch + merge)
git fetchBusca alterações do remoto SEM fazer merge (mais seguro)
⏪️ Desfazendo Alterações
ComandoO que fazSeguro em público?
git stashGuarda alterações não commitadas temporariamente✅ Sim
git stash popRecupera alterações guardadas no stash✅ Sim
git revert <commit>Cria novo commit que desfaz o commit indicado✅ Sim
git reset <commit>Move HEAD para outro commit (pode reescrever histórico)⚠️ Cuidado
git tag <nome>Cria uma marcação no commit atual (ex: v1.0)✅ Sim
↔️ git fetch vs git pull
# git pull = git fetch + git merge (automático) $ git pull remote: Enumerating objects: 5, done. Updating a3f8c12..d9e2b47 Fast-forward # git fetch: baixa sem mesclar — você inspeciona antes $ git fetch remote: Enumerating objects: 5, done. $ git log --oneline origin/main # inspeciona $ git merge origin/main # mescla quando pronto
⚠️ git reset — os três modos
ModoO que resetaWorking Dir
--softSó move o HEAD (commits desfeitos mas arquivos no staging)Intacto
--mixed (padrão)Move HEAD e limpa staging (arquivos ficam modificados)Intacto
--hardMove HEAD, limpa staging E descarta alterações — IRREVERSÍVEL⚠ Apagado

🚀 Curiosidades — Remotos e Desfazendo
🌐
GitHub não é Git
Git é o sistema de controle de versão (instalado localmente). GitHub, GitLab e Bitbucket são serviços de hospedagem de repositórios Git na nuvem. Você pode usar Git sem GitHub.
🧳
git stash é uma pilha
O git stash funciona como uma pilha (stack): você pode guardar vários "estados" com git stash push -m "descricao" e recuperar qualquer um com git stash apply stash@{2}.
🏷️
Tags são imutáveis por convenção
Existem duas tags no Git: lightweight (só um ponteiro) e annotated (git tag -a v1.0 -m "Release"). Annotated tags são assinadas e incluem metadados — preferidas para releases.
🔒
git reflog é o "desfazer máximo"
O git reflog guarda um histórico de TUDO que aconteceu com o HEAD nos últimos 90 dias. É possível recuperar commits perdidos com git reset --hard ou até branches deletadas acidentalmente.
🌍
O GitHub hospeda +100 milhões de repositórios
O GitHub ultrapassou a marca de 100 milhões de repositórios e mais de 100 milhões de desenvolvedores em 2023. Foi adquirido pela Microsoft em 2018 por US$ 7,5 bilhões.
