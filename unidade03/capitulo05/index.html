Separação entre Lógica e Interface com FXML FXML

Em um projeto tradicional, todo o código da interface gráfica e toda a lógica da aplicação podem acabar misturados no mesmo arquivo Java. Com o tempo, isso dificulta tanto a leitura quanto a manutenção.

O que é FXML? Uma linguagem declarativa (baseada em XML) usada para definir a estrutura da interface gráfica no JavaFX, sem precisar codificar isso diretamente em Java.

Declarativo Baseado em XML Separação de Responsabilidades
Exemplo FXML + Java 3 arquivos

Depois de configurado o ambiente JavaFX no projeto, criamos um arquivo .fxml definindo a interface:

<?xml version="1.0" encoding="UTF-8"?> <?import javafx.scene.control.Button?> <?import javafx.scene.layout.AnchorPane?> <AnchorPane xmlns:fx="http://javafx.com/fxml" fx:controller="ex45fxmlaplication.Controller" prefWidth="300" prefHeight="150"> <Button text="Enviar" layoutX="100" layoutY="60" onAction="#enviarMensagem"/> </AnchorPane>

Em seguida, criamos a classe Controller, que conecta a interface FXML à lógica Java através da anotação @FXML:

package ex45fxmlaplication; import javafx.fxml.FXML; public class Controller { @FXML public void enviarMensagem() { System.out.println("Mensagem enviada pelo botao!"); } }

Por fim, a classe principal usa FXMLLoader para carregar o arquivo FXML e exibi-lo:

package ex45fxmlaplication; import javafx.application.Application; import javafx.fxml.FXMLLoader; import javafx.scene.Parent; import javafx.scene.Scene; import javafx.stage.Stage; public class Ex45FXMLAplication extends Application { @Override public void start(Stage stage) throws Exception { Parent root = FXMLLoader.load(getClass().getResource("Interface.fxml")); Scene scene = new Scene(root); stage.setTitle("Exemplo FXML"); stage.setScene(scene); stage.show(); } public static void main(String[] args) { launch(args); } }
Vantagens da Separação FXML + Java
  • Código mais limpo: Java para lógica, FXML para visual
  • Facilidade de manutenção: mudanças visuais não afetam o código de lógica
  • Colaboração em equipe: designers trabalham no visual, programadores no funcionamento
  • Escalabilidade: ideal para projetos grandes com interfaces complexas
Scene Builder Editor Visual

O Scene Builder é uma ferramenta gráfica desenvolvida para criar a interface visual de uma aplicação JavaFX.

Permite montar telas com botões, campos de texto, rótulos e layouts apenas arrastando os componentes para o palco, sem precisar escrever código XML manualmente. Pode ser baixado em gluonhq.com/products/scene-builder.

Exemplo com Scene Builder Passo a passo

Depois de instalado, crie o projeto normalmente no NetBeans e adicione um arquivo FXML vazio. Abra-o com o Scene Builder e arraste os componentes desejados (Label, TextField, Button) para o palco.

Para cada componente, defina na aba Code do Inspector:

  • Para o TextField: fx:id = campoNome
  • Para o Button: onAction = #mostrarNome

Isso cria a ligação entre o componente visual e o código no Controller Java. O FXML gerado automaticamente pelo Scene Builder fica assim:

<AnchorPane prefHeight="300" prefWidth="400" xmlns:fx="http://javafx.com/fxml/1" fx:controller="ex46scenebuilder.TelaPrincipalController"> <children> <Label layoutX="31.0" layoutY="36.0" text="Nome:" /> <TextField fx:id="campoNome" layoutX="75.0" layoutY="32.0" /> <Button layoutX="239.0" layoutY="32.0" onAction="#mostrarNome" text="Enviar" /> </children> </AnchorPane>

E a classe controladora, que lê o campo e imprime no console:

package ex46scenebuilder; import javafx.fxml.FXML; import javafx.scene.control.TextField; public class TelaPrincipalController { @FXML private TextField campoNome; @FXML public void mostrarNome() { String nome = campoNome.getText(); System.out.println("Nome digitado: " + nome); } }
Estilizando com CSS Aparência

A aparência da interface é tão importante quanto sua funcionalidade. Em JavaFX, você pode transformar visualmente sua aplicação com o poder do CSS.

Com CSS, você pode alterar:

  • Cores de fundo e de texto
  • Bordas e seus contornos
  • Tamanho e estilo de fontes
  • Tamanhos, margens e preenchimentos (padding)
  • Efeitos visuais como gradientes, sombras, transições

JavaFX utiliza propriedades específicas com prefixo -fx-, que não existem no CSS da web. Por exemplo: -fx-background-color, -fx-border-color, -fx-text-fill.

Estilizando com CSS: Exemplo .button {}

Vamos estilizar o botão "Enviar" do exemplo anterior, criando um arquivo style.css que altera sua aparência:

.button { -fx-background-color: #2ecc71; -fx-text-fill: white; -fx-font-weight: bold; -fx-font-size: 14px; -fx-cursor: hand; -fx-background-radius: 5; -fx-border-color: #27ae60; -fx-border-width: 2; -fx-border-radius: 5; }

Para aplicar o CSS, adicionamos o atributo stylesheets no componente raiz do arquivo .fxml:

<AnchorPane prefHeight="300" prefWidth="400" xmlns:fx="http://javafx.com/fxml/1" stylesheets="@style.css">

Com isso, o botão "Enviar" passa a ter fundo verde-esmeralda, texto branco em negrito e cantos arredondados — sem alterar uma linha sequer do código Java.

🚀 Curiosidades sobre FXML e CSS
🏗
FXML é o "MVC" nativo do JavaFX
O padrão FXML + Controller é, na prática, uma implementação do padrão MVC (Model-View-Controller): o FXML é a View, o Controller é o Controller, e as classes de domínio da aplicação fazem o papel de Model.
🧰
O # antes do nome do método não é acaso
Em onAction="#enviarMensagem", o # indica ao FXMLLoader que enviarMensagem é uma referência a um método do Controller — sem ele, o FXML tentaria interpretar o valor como uma expressão de binding.
🖥
Scene Builder é feito com... JavaFX
O próprio Scene Builder, mantido pela Gluon, é uma aplicação escrita em JavaFX — a ferramenta usa a mesma tecnologia que ela ajuda a construir.
🎭
Pseudo-classes também existem no JavaFX CSS
Assim como :hover na web, o JavaFX CSS suporta pseudo-classes como :hover, :pressed e :focused — dá para estilizar o botão de forma diferente quando o mouse passa por cima ou quando ele está pressionado.
📦
Um CSS pode estilizar toda a aplicação
O atributo stylesheets pode ser aplicado na Scene inteira (via scene.getStylesheets().add(...)) em vez de em cada FXML individualmente — útil para manter um tema visual consistente em toda a aplicação.
