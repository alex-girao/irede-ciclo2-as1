O que é um Wildcard (?) Curinga de Tipo

Wildcards (?) permitem que um método ou uma estrutura trabalhe com diferentes tipos sem precisar definir um tipo exato.

Uso comum: em métodos genéricos, evitando a necessidade de um tipo fixo, e em classes genéricas, para permitir maior flexibilidade.

? — qualquer tipo ? extends T — leitura ? super T — escrita
Exemplo de Uso do Wildcard (?) List<?>

Aqui, List<?> significa "uma lista de qualquer tipo". Você pode ler os dados da lista (porque todos os elementos podem ser tratados como Object), mas não pode adicionar elementos (exceto null), pois não sabemos o tipo exato da lista.

public class Util { public static void imprimirLista(List<?> lista) { // lista de qualquer tipo for (Object item : lista) { System.out.println(item); } } }

Testando imprimirLista():

List<String> listaStrings = Arrays.asList("Java", "Generics", "Wildcard"); List<Integer> listaInteiros = Arrays.asList(10, 20, 30); Util.imprimirLista(listaStrings); Util.imprimirLista(listaInteiros);
? extends T — Leitura com Segurança Somente Leitura

? extends T permite ler elementos de uma lista sem risco. Aceita qualquer tipo que seja T ou uma subclasse de T, mas só permite leitura, não modificação.

CLASSE BASE — PESSOA
public class Pessoa { private String nome; public Pessoa(String nome) { this.nome = nome; } public String getNome() { return nome; } }
SUBCLASSE — FUNCIONARIO
public class Funcionario extends Pessoa { public Funcionario( String nome) { super(nome); } }

A classe Util tem um método genérico mostrarNomes(List<? extends Pessoa> pessoas), que aceita qualquer lista cujos elementos herdem de Pessoa:

public class Util { public static void mostrarNomes(List<? extends Pessoa> pessoas) { for (Pessoa p : pessoas) { System.out.println(p.getNome()); } } }
? super T — Escrita com Segurança Escrita Permitida

? super T permite adicionar elementos com segurança. Aceita qualquer superclasse de T. Você pode adicionar elementos, mas a leitura é limitada — cada item só pode ser tratado como Object.

A classe Util tem um método genérico adicionarPessoa(List<? super Funcionario> lista), que aceita qualquer lista cuja classe seja Funcionario ou uma superclasse dele (as classes Pessoa e Funcionario são as mesmas do exemplo anterior):

public class Util { public static void adicionarPessoa(List<? super Funcionario> lista) { lista.add(new Funcionario("Novo Funcionario")); } }

Usando adicionarPessoa():

List<Pessoa> listaPessoas = new ArrayList<>(); // lista de Pessoa Util.adicionarPessoa(listaPessoas); // adicionando um Funcionario à lista for (Pessoa p : listaPessoas) { System.out.println("Nome: " + p.getNome()); }

Aplicações Práticas — List<? extends Number> Integração com Collections

Wildcards são amplamente usados na API Collections (List, Set, Map, Queue), facilitando a escrita de métodos que trabalham com diferentes coleções genéricas.

List<? extends Number> permite aceitar qualquer subclasse de Number, como Integer, Double e Float:

public class MathUtil { public static double calcularSoma(List<? extends Number> numeros) { double soma = 0; for (Number n : numeros) { soma += n.doubleValue(); // converte qualquer Number para double } return soma; } }

Com ? extends Number, criamos um único método que aceita qualquer tipo numérico sem perder segurança — evitando a necessidade de múltiplos métodos sobrecarregados (Integer, Double, Float).

Questão 1 — List<?> significa "lista de qualquer tipo" e permite ler os elementos, mas não adicionar (exceto null).
Questão 2 — Com uma lista declarada como List<? extends Pessoa>, é seguro adicionar um novo objeto Funcionario nela.
Questão 3 — ? super T aceita qualquer superclasse de T e permite adicionar elementos do tipo T com segurança.
Questão 4 — Ao ler um elemento de uma List<? super Funcionario>, o tipo garantido pelo compilador é sempre Funcionario, sem necessidade de cast.
Questão 5 — List<? extends Number> permite escrever um único método que aceita List<Integer>, List<Double> ou List<Float>, sem sobrecarga.

🚀 Curiosidades sobre Wildcards
🧩
PECS — Producer Extends, Consumer Super
Regra mnemônica para escolher o wildcard certo: use ? extends T quando a coleção só produz valores (você lê dela); use ? super T quando ela só consome valores (você escreve nela).
🔒
Por que ? extends não permite adicionar?
Uma List<? extends Pessoa> pode, na verdade, ser uma List<Funcionario>. Se o compilador permitisse adicionar uma Pessoa genérica ali, você poderia inserir o tipo errado numa lista mais específica — por isso a escrita é bloqueada.
⚖
List<Object> não é o mesmo que List<?>
Parece a mesma coisa, mas não é: em List<Object> você pode adicionar qualquer objeto. Em List<?>, o compilador não sabe qual é o tipo real da lista, então só permite adicionar null.
📚
Usado o tempo todo no Java Collections Framework
Métodos como Collections.copy(List<? super T> dest, List<? extends T> src) usam exatamente os dois wildcards deste capítulo juntos — src só é lido, dest só recebe escrita.
🚫
Não existe ? extends T super K
Um wildcard só pode ter um limite: ou extends, ou super, nunca os dois ao mesmo tempo. Se precisar de mais flexibilidade, geralmente o método genérico com <T> é a melhor escolha.
