O que são Generics? Tipos Parametrizados

Até agora, usamos classes e métodos que operam com tipos específicos ou com o tipo Object.

Problema sem Generics: erros por conversões erradas de tipo (cast) e código menos seguro e menos reutilizável.

Solução com Generics: código mais seguro — sem necessidade de cast — e reutilizável, já que uma mesma classe ou método pode funcionar para qualquer tipo.

Tipo Parametrizado <T> Segurança de Tipo Reutilização Sem Cast
Motivação — Sem Generics vs. Com Generics Comparação

Um ArrayList sem tipo definido aceita qualquer tipo de objeto. Para recuperar um valor, é preciso fazer um cast — e se o cast estiver errado, o programa quebra em tempo de execução.

SEM GENERICS — RISCO DE ERRO
ArrayList lista = new ArrayList(); lista.add("Texto"); // precisamos fazer cast String s = (String) lista.get(0); System.out.println(s);
COM GENERICS — SEGURO
ArrayList<String> lista = new ArrayList<>(); lista.add("Texto"); // sem necessidade de cast! String s = lista.get(0); System.out.println(s);

Vantagens dos Generics: evita conversões desnecessárias · garante que apenas o tipo correto seja armazenado · deixa o código mais limpo e fácil de manter.

Criação de Classes Genéricas class Caixa<T>

Uma classe genérica declara um parâmetro de tipo — por convenção chamado T — que só é definido na hora de criar o objeto.

public class Caixa<T> { // classe genérica com parâmetro de tipo <T> private T item; public void guardar(T item) { this.item = item; } public T abrir() { return item; } }

Usando Caixa<T>:

Caixa<String> caixa1 = new Caixa<>(); caixa1.guardar("Livro"); System.out.println("Item guardado: " + caixa1.abrir()); Caixa<Integer> caixa2 = new Caixa<>(); caixa2.guardar(123); System.out.println("Item guardado: " + caixa2.abrir());

Código reutilizável: Caixa funciona para qualquer tipo. Segurança de tipo: caixa1 só aceita String e caixa2 só aceita Integer.

Métodos Genéricos Reutilização

Podemos criar métodos genéricos dentro de classes normais (não genéricas) para realizar operações comuns em qualquer tipo de dado.

public class Util { public static <T> void imprimir(T valor) { System.out.println(valor); } }

Chamando o método:

Util.imprimir("Olá, mundo!"); // String Util.imprimir(100); // Integer Util.imprimir(3.14); // Double

Vantagens: são reutilizáveis — aceitam diferentes tipos — e reduzem a duplicação de código.

Interfaces Genéricas Contrato Reutilizável

Interfaces genéricas permitem que diferentes classes sigam um modelo padrão, mas para tipos diferentes. Um exemplo clássico é um repositório de CRUD (Create, Read, Update, Delete):

public interface Repositorio<T> { // Interface Genérica <T> void salvar(T entidade); // Criar ou salvar uma entidade T buscarPorId(int id); // Buscar por ID void atualizar(T entidade); // Atualizar dados void deletar(int id); // Remover entidade List<T> listarTodos(); // Retornar lista de todas as entidades }

Implementação para Produto:

public class RepositorioDeProdutos implements Repositorio<Produto> { private List<Produto> produtos = new ArrayList<>(); @Override public void salvar(Produto produto) { produtos.add(produto); } @Override public Produto buscarPorId(int id) { return produtos.get(id); } // ... atualizar(), deletar() e listarTodos() seguem o mesmo princípio }

Questão 1 — Generics permitem escrever código que funciona com qualquer tipo, mantendo a segurança de tipos verificada em tempo de compilação.
Questão 2 — Em um ArrayList sem Generics, é possível adicionar qualquer tipo de objeto na mesma lista, sem restrição.
Questão 3 — Ao usar ArrayList<String>, não é mais necessário fazer cast ao recuperar um elemento com get().
Questão 4 — Uma classe declarada como class Caixa<T> só pode ser instanciada usando o tipo String.
Questão 5 — Em public static <T> void imprimir(T valor), o método declara seu próprio parâmetro de tipo, mesmo estando dentro de uma classe não genérica.

🚀 Curiosidades sobre Generics
📅
Generics chegaram no Java 5 (2004)
Antes disso, todo o Java Collections Framework (ArrayList, HashMap, etc.) trabalhava apenas com Object, exigindo cast manual em todo lugar.
💎
O Diamond Operator <>
Até o Java 6, era preciso repetir o tipo dos dois lados: ArrayList<String> lista = new ArrayList<String>();. Desde o Java 7 (2011), o compilador infere o tipo: new ArrayList<>();
👻
Type Erasure — os tipos "somem" em tempo de execução
O compilador usa a informação de <T> só para checar tipos na compilação, e depois a apaga. Em tempo de execução, Caixa<String> e Caixa<Integer> são exatamente a mesma classe Caixa.
🚫
Generics não aceitam tipos primitivos
Não existe Caixa<int>. É preciso usar o wrapper Caixa<Integer> — o Java converte automaticamente entre int e Integer pelo autoboxing.
⛔
Não dá para fazer new T()
Por causa do type erasure, o compilador não sabe qual construtor chamar em tempo de execução — por isso new T() dentro de uma classe genérica é proibido.
🧩
PECS — Producer Extends, Consumer Super
Regra mnemônica avançada para os wildcards ? extends T e ? super T, muito usada dentro do próprio Java Collections Framework. Veremos isso em capítulos futuros!
