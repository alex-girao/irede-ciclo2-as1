O que é um Banco de Dados Relacional? Tabelas & Relações

O modelo relacional é amplamente utilizado na maioria dos sistemas de informação. Ele se baseia na organização dos dados em tabelas (ou relações), que podem ser visualizadas como planilhas compostas por linhas e colunas.

Cada tabela armazena dados relacionados a uma entidade (como usuários, produtos, pedidos), e cada linha representa um registro único dessa entidade. As colunas correspondem aos atributos da entidade — por exemplo: nome, email, idade, etc.

Tabela = Entidade Linha = Registro Coluna = Atributo
A Origem do Banco de Dados Relacional Linha do Tempo
1950–1960
Modelos Antecessores
Modelo Hierárquico: organiza dados como uma árvore pai-filho, rígido e de difícil manutenção. Modelo em Rede: mais flexível, mas exige navegação manual e é complexo de implementar.
1970
A Revolução de Codd
Edgar F. Codd publica "A Relational Model of Data for Large Shared Data Banks", introduzindo tabelas relacionais, chaves primárias e estrangeiras, e operações declarativas (SELECT, JOIN, PROJECT) — separando a lógica dos dados do armazenamento físico.
1970–1980
Primeiros SGBDs
System R (protótipo da IBM baseado no modelo de Codd) abre caminho para Ingres (Berkeley), Oracle (1977), DB2 (IBM, 1983) e SQL Server (Microsoft, 1989).
1990–hoje
Legado Duradouro
Mais de 50 anos depois, o modelo relacional ainda domina sistemas financeiros e bancários, plataformas de e-commerce, ERPs e aplicações corporativas e web.
Chave Primária e Chave Estrangeira PK & FK

Chave primária (Primary Key): campo (ou conjunto de campos) que identifica de forma única cada linha de uma tabela. Deve ser única e não pode ser nula.

Chave estrangeira (Foreign Key): campo em uma tabela que referencia a chave primária de outra, conectando entidades diferentes e garantindo a integridade referencial — os dados relacionados precisam existir no banco.

O que é SQL? Structured Query Language

SQL é a linguagem padrão para gerenciar e manipular dados em bancos relacionais (MySQL, PostgreSQL, Oracle, SQL Server...). Com ela realizamos:

CREATE — criar estruturas INSERT — inserir dados SELECT — consultar UPDATE — atualizar DELETE — remover

Criando a tabela usuarios:

CREATE TABLE usuarios ( id_usuario INT PRIMARY KEY, nome VARCHAR(100), email VARCHAR(100) );
Manipulando Dados com SQL INSERT · UPDATE · DELETE

INSERT: adiciona novos registros à tabela.

INSERT INTO usuarios (id_usuario, nome, email) VALUES (1, 'Ana Souza', 'ana@email.com');

UPDATE: altera registros existentes — a cláusula WHERE define quais linhas serão afetadas.

UPDATE usuarios SET email = 'ana.souza@novaempresa.com' WHERE id_usuario = 1;

DELETE: remove registros — sem WHERE, remove todas as linhas da tabela!

DELETE FROM usuarios WHERE id_usuario = 2;
O que é JDBC? Java Database Connectivity

JDBC é uma API da linguagem Java que permite a comunicação entre aplicações Java e bancos de dados relacionais. Por meio dela, o desenvolvedor pode:

Conectar ao banco Executar SQL Receber resultados Tratar exceções

Arquitetura em camadas:

Java Applications ↓ JDBC API ↓ JDBC Driver Manager ↓ JDBC Driver ↓ DBMS

O JDBC Driver Manager escolhe, entre os drivers registrados, aquele capaz de conversar com o banco de dados de destino (MySQL, PostgreSQL, Oracle...).

Ciclo de conexão com JDBC: Registrar o Driver → Estabelecer a Conexão → Executar Comandos SQL → Processar Resultados → Fechar a Conexão.

Conectando Java ao Banco via JDBC Maven + MySQL

Com o MySQL instalado e um banco criado, adicionamos o driver JDBC como dependência no pom.xml do projeto Maven:

<dependency> <groupId>mysql</groupId> <artifactId>mysql-connector-java</artifactId> <version>8.0.33</version> </dependency>

Centralizamos a conexão em uma classe de fábrica:

public class ConexaoFactory { private static final String URL = "jdbc:mysql://localhost:3306/meubanco"; private static final String USUARIO = "root"; private static final String SENHA = "sua_senha"; public static Connection conectar() throws SQLException { return DriverManager.getConnection(URL, USUARIO, SENHA); } }

Executando uma consulta a partir do Java:

try (Connection con = ConexaoFactory.conectar()) { Statement stmt = con.createStatement(); ResultSet rs = stmt.executeQuery("SELECT * FROM usuarios"); while (rs.next()) { System.out.println( rs.getInt("id_usuario") + " - " + rs.getString("nome") + " - " + rs.getString("email") ); } } catch (SQLException e) { e.printStackTrace(); }
Boas Práticas com o JDBC Segurança & Manutenção

Trabalhar com JDBC exige não apenas escrever código funcional, mas também aplicar boas práticas que melhoram a segurança, a legibilidade e a manutenção do projeto:

Sempre feche conexões, statements e result sets: todo recurso aberto com o banco consome memória e mantém portas abertas. Não fechá-los pode causar vazamentos de memória e sobrecarregar o sistema com conexões abandonadas.

Use PreparedStatement para evitar SQL Injection: ele evita que valores maliciosos inseridos pelo usuário quebrem a lógica SQL da aplicação.

Centralize a lógica de conexão: mantenha toda a lógica de conexão concentrada em uma única classe (como a ConexaoFactory).

🚀 Curiosidades sobre Banco de Dados e JDBC
📄
O paper que mudou tudo
Em 1970, o pesquisador da IBM Edgar F. Codd publicou "A Relational Model of Data for Large Shared Data Banks", criando a base teórica que todo banco de dados relacional usa até hoje.
🔤
SQL já se chamou SEQUEL
O System R, protótipo da IBM baseado no modelo de Codd, usava uma linguagem chamada SEQUEL (Structured English Query Language). O nome foi encurtado para SQL por questões de marca registrada.
🔐
SQL Injection é um dos ataques mais antigos da web
Concatenar texto vindo do usuário direto em um comando SQL permite que ele injete comandos maliciosos. O PreparedStatement do JDBC trata os valores como dados, nunca como código SQL.
🧩
JDBC é só um contrato
A API java.sql define interfaces como Connection e Statement. Quem implementa de fato é o driver de cada fabricante (MySQL, PostgreSQL, Oracle...) — por isso é preciso adicionar o driver certo como dependência.
🗄
Nem tudo é relacional
A partir dos anos 2000, bancos NoSQL (como MongoDB e Redis) surgiram como alternativa para dados sem estrutura fixa ou que exigem altíssima escala — mas o modelo relacional continua sendo a escolha padrão para dados estruturados e transacionais.
🏗
O primeiro Oracle nem se chamava Oracle
A empresa fundada em 1977 por Larry Ellison chamava-se Software Development Laboratories. Seu produto de banco de dados relacional, batizado Oracle, acabou dando nome à própria empresa.
