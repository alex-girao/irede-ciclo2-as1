1)
Criar a Classe ConexaoFactory
Básico
Crie uma classe ConexaoFactory que centraliza a lógica de conexão com um banco MySQL chamado meubanco, rodando em localhost:3306.
Requisitos
  • Declare constantes URL, USUARIO e SENHA
  • Implemente public static Connection conectar() throws SQLException
  • Use DriverManager.getConnection(URL, USUARIO, SENHA) para obter a conexão
Solução
import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; public class ConexaoFactory { private static final String URL = "jdbc:mysql://localhost:3306/meubanco"; private static final String USUARIO = "root"; private static final String SENHA = "sua_senha"; public static Connection conectar() throws SQLException { return DriverManager.getConnection(URL, USUARIO, SENHA); } }
💡 Substitua "sua_senha" pela senha que você definiu ao instalar o MySQL, e não se esqueça de adicionar o driver mysql-connector-java no pom.xml.
2)
Listar Usuários com Statement e ResultSet
Básico
Usando a ConexaoFactory do exercício anterior, escreva um programa que conecta ao banco, executa SELECT * FROM usuarios e imprime cada linha no console.
Requisitos
  • Obtenha a conexão com ConexaoFactory.conectar()
  • Crie um Statement e execute executeQuery("SELECT * FROM usuarios")
  • Percorra o ResultSet com while (rs.next()), imprimindo id_usuario, nome e email
  • Trate SQLException com um bloco catch
Solução
import java.sql.Connection; import java.sql.ResultSet; import java.sql.Statement; public class Ex02ListarUsuarios { public static void main(String[] args) { try (Connection con = ConexaoFactory.conectar()) { Statement stmt = con.createStatement(); ResultSet rs = stmt.executeQuery("SELECT * FROM usuarios"); while (rs.next()) { System.out.println( rs.getInt("id_usuario") + " - " + rs.getString("nome") + " - " + rs.getString("email") ); } } catch (Exception e) { e.printStackTrace(); } } }
Saída esperada no console
1 - Ana Souza - ana@email.com 2 - João Lima - joao@email.com
💡 O try (Connection con = ...) é um try-with-resources: a conexão é fechada automaticamente ao final do bloco, mesmo se ocorrer uma exceção.
3)
Inserir um Usuário com PreparedStatement
Intermediário
Escreva um método inserirUsuario que recebe id, nome e email, e insere um novo registro na tabela usuarios usando PreparedStatement (evitando SQL Injection).
Requisitos
  • Use "INSERT INTO usuarios (id_usuario, nome, email) VALUES (?, ?, ?)" como SQL parametrizado
  • Preencha os parâmetros com setInt() e setString()
  • Execute com executeUpdate(), já que não há resultado a ser lido
Solução
import java.sql.Connection; import java.sql.PreparedStatement; public class Ex03InserirUsuario { public static void inserirUsuario(int id, String nome, String email) { String sql = "INSERT INTO usuarios (id_usuario, nome, email) VALUES (?, ?, ?)"; try (Connection con = ConexaoFactory.conectar(); PreparedStatement stmt = con.prepareStatement(sql)) { stmt.setInt(1, id); stmt.setString(2, nome); stmt.setString(3, email); stmt.executeUpdate(); System.out.println("Usuário inserido com sucesso!"); } catch (Exception e) { e.printStackTrace(); } } public static void main(String[] args) { inserirUsuario(3, "Carlos Souza", "carlos@email.com"); } }
Saída esperada no console
Usuário inserido com sucesso!
💡 Os pontos de interrogação (?) são preenchidos por posição (1, 2, 3...), na mesma ordem em que aparecem no SQL.
4)
Atualizar o E-mail de um Usuário
Intermediário
Escreva um método atualizarEmail que recebe um id e um novoEmail, e atualiza apenas o e-mail do usuário correspondente, usando PreparedStatement.
Requisitos
  • Use "UPDATE usuarios SET email = ? WHERE id_usuario = ?" como SQL parametrizado
  • Verifique quantas linhas foram afetadas usando o retorno de executeUpdate()
  • Imprima uma mensagem informando se o usuário foi encontrado e atualizado, ou não
Solução
import java.sql.Connection; import java.sql.PreparedStatement; public class Ex04AtualizarEmail { public static void atualizarEmail(int id, String novoEmail) { String sql = "UPDATE usuarios SET email = ? WHERE id_usuario = ?"; try (Connection con = ConexaoFactory.conectar(); PreparedStatement stmt = con.prepareStatement(sql)) { stmt.setString(1, novoEmail); stmt.setInt(2, id); int linhasAfetadas = stmt.executeUpdate(); if (linhasAfetadas > 0) { System.out.println("E-mail atualizado com sucesso!"); } else { System.out.println("Nenhum usuário encontrado com esse ID."); } } catch (Exception e) { e.printStackTrace(); } } public static void main(String[] args) { atualizarEmail(1, "ana.souza@novaempresa.com"); } }
Saída esperada no console
E-mail atualizado com sucesso!
5)
CRUD Simples com Fechamento Seguro de Recursos
Intermediário
Escreva um método removerUsuario que recebe um id, remove o usuário correspondente com PreparedStatement, e em seguida lista os usuários restantes — tudo usando try-with-resources para garantir o fechamento correto de cada recurso.
Requisitos
  • Use "DELETE FROM usuarios WHERE id_usuario = ?" em um PreparedStatement
  • Abra Connection, PreparedStatement (e, se precisar de outra consulta, Statement/ResultSet) sempre dentro de um bloco try (...)
  • Após remover, execute um SELECT * FROM usuarios e imprima a lista restante
Solução
import java.sql.Connection; import java.sql.PreparedStatement; import java.sql.ResultSet; import java.sql.Statement; public class Ex05RemoverUsuario { public static void removerUsuario(int id) { String sqlDelete = "DELETE FROM usuarios WHERE id_usuario = ?"; try (Connection con = ConexaoFactory.conectar(); PreparedStatement stmtDelete = con.prepareStatement(sqlDelete)) { stmtDelete.setInt(1, id); stmtDelete.executeUpdate(); System.out.println("Usuário removido. Lista atualizada:"); try (Statement stmtSelect = con.createStatement(); ResultSet rs = stmtSelect.executeQuery("SELECT * FROM usuarios")) { while (rs.next()) { System.out.println( rs.getInt("id_usuario") + " - " + rs.getString("nome") ); } } } catch (Exception e) { e.printStackTrace(); } } public static void main(String[] args) { removerUsuario(2); } }
Saída esperada no console
Usuário removido. Lista atualizada: 1 - Ana Souza 3 - Carlos Souza
💡 Cada recurso aberto em um try (...) é fechado automaticamente na ordem inversa em que foi aberto, mesmo em caso de exceção — é a forma mais segura de trabalhar com JDBC.
