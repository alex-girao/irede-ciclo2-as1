O que é um Pacote? package

Pacotes em Java são estruturas organizacionais usadas para agrupar classes relacionadas dentro de um projeto. Eles funcionam como pastas, separando responsabilidades e facilitando a manutenção do código.

ANALOGIA: Armário organizado
📂 model/ — entidades 📂 service/ — lógica 📂 exceptions/ — erros 📂 controllers/ — controle
// Declarar o pacote — PRIMEIRA linha do arquivo package com.mycompany.ex28pacotes.models; public class Cliente { private String nome; // ... }
Convenção de Nomeação de Pacotes domínio invertido

Pacotes seguem duas regras fundamentais: tudo em minúsculo e domínio da empresa em ordem invertida, garantindo unicidade global.

Domínio da EmpresaFormato do Pacote
empresa.com.brbr.com.empresa.sistema
universidade.orgorg.universidade.controle
mycompany.comcom.mycompany.sistema.model
minúsculas domínio invertido separador: ponto (.)
Importação de Classes import

A instrução import permite usar o nome simples de uma classe de outro pacote, evitando escrever o nome qualificado completo toda vez.

package com.mycompany.ex28pacotes; // Importando classes de outros pacotes import com.mycompany.ex28pacotes.models.Cliente; import com.mycompany.ex28pacotes.models.controllers.ClienteController; public class Ex28Pacotes { public static void main(String[] args) { Cliente c = new Cliente(); ClienteController cc = new ClienteController(); cc.salvarCliente(); } }
Sem import, seria necessário escrever o nome completo: com.mycompany.ex28pacotes.models.Cliente c = new com.mycompany.ex28pacotes.models.Cliente();
Estrutura de Diretórios do Projeto organização

A estrutura de pastas do projeto deve espelhar a estrutura de pacotes das classes. Cada subpasta tem uma responsabilidade clara.

src/ ├─ model/ # Entidades do sistema │ ├─ Livro.java │ └─ Usuario.java ├─ service/ # Lógica de negócios │ └─ BibliotecaService.java ├─ exceptions/ # Tratamento de erros │ └─ LivroIndisponivelException.java └─ Main.java # Ponto de entrada
Subpacotes e Hierarquia subpacotes

Pacotes podem conter subpacotes, formando hierarquias que organizam ainda mais o projeto. Cada classe declara seu pacote exato na primeira linha.

models/Cliente.java
package com.mycompany .ex28pacotes.models; public class Cliente { private String nome; // getters / setters }
models/controllers/ClienteController.java
package com.mycompany .ex28pacotes .models.controllers; public class ClienteController { public void salvarCliente() { System.out.println("Salvo!"); } }

🚀 Curiosidades sobre Pacotes e Organização
✨ java.lang é importado automaticamente

O pacote java.lang (que contém String, System, Math, Object etc.) é o único importado automaticamente pelo compilador. Todos os outros precisam de import explícito.

🔓 Acesso package-private

Membros sem modificador de acesso (public, private ou protected) têm acesso package-private: visíveis apenas dentro do mesmo pacote. É o padrão de acesso "amigo do vizinho de bairro".

⚠ import java.util.Date vs java.sql.Date

Duas classes podem ter o mesmo nome simples em pacotes diferentes. Se precisar usar ambas no mesmo arquivo, uma deve ser importada e a outra referenciada pelo nome qualificado completo: java.sql.Date sqlDate = new java.sql.Date(...);

📦 Wildcard import não importa subpacotes

import java.util.* importa todas as classes de java.util, mas NÃO os subpacotes. java.util.concurrent.locks.Lock precisaria de import próprio. Além disso, wildcard pode tornar o código menos legível.

🔨 Estrutura Maven: src/main/java

Em projetos gerenciados pelo Maven (ou Gradle), a estrutura padrão coloca o código-fonte em src/main/java e os testes em src/test/java. Esta é a estrutura utilizada pelo NetBeans, Eclipse e IntelliJ quando você cria um projeto Maven.

🌐 Domínio invertido é convenção universal

A convenção de domínio invertido (com.empresa) surgiu para garantir unicidade global dos pacotes, especialmente em distribuição de bibliotecas. É a mesma convenção usada em Android (com.example.myapp) e no Maven Central Repository.
